Bloque 1 — Estructuras y memoria dinámica

Los 5 structs jerárquicos y las tres funciones obligatorias de manejo de arreglos dinámicos.

✓ Aprobado — 15% + 10% de la rúbrica de memoria dinámica
📋
"Fecha debe manejarse con char[]" · "Universidad → Programas → Estudiantes → Matrículas" (relación obligatoria de 3 niveles).

Cajas dentro de cajas

La Universidad no guarda estudiantes directamente: guarda Programas, y cada programa guarda sus propios estudiantes. Cada nivel tiene un arreglo del nivel siguiente + su contador.

¿Por qué el contador?

Un puntero como Estudiante* solo guarda una dirección. No sabe cuántos elementos hay detrás — por eso estudiantesCount es obligatorio, no un capricho.

Fecha
struct Fecha{
    char anio[5];
    char mes[3];
    char dia[3];
};

char[], no int: el enunciado lo exige explícito. Tamaños con espacio para el '\0' final: "2026" son 4 caracteres + terminador = anio[5]; "09" son 2 + terminador = mes[3]/dia[3].

Matricula
struct Matricula{
    int id;
    char codigoMateria[10];
    char nombreMateria[40];
    float notas[3];
    float definitiva;
    Fecha fecha;
};

Es el nivel más profundo de la jerarquía — no tiene arreglo de "hijos", solo datos propios. fecha es un struct dentro de otro struct (composición), y notas[3] es fijo porque el enunciado dice siempre 3 notas por materia.

Estudiante y Programa
struct Estudiante{
    int id;
    char nombre[50];
    char documento[20];
    char telefono[20];
    Matricula *matriculas;
    int matriculasCount;
};

struct Programa{
    int codigo;
    char nombre[50];
    Estudiante *estudiantes;
    int estudiantesCount;
};

Ambos repiten el mismo patrón: datos propios + Tipo *arreglo + arregloCount. Estudiante apunta hacia sus Matriculas, Programa apunta hacia sus Estudiantes — así se arma la cadena de 3 niveles sin que ningún nivel conozca al de más arriba.

Universidad
struct Universidad{
    Programa *programas;
    int programasCount;
};

La raíz de la jerarquía. Una sola variable global Universidad universidad = {nullptr, 0}; es el punto de entrada a todos los datos del programa — todo lo demás cuelga de ahí.

agregarPrograma() en 3 partes — el patrón de crecimiento que se repite en las otras dos funciones.

1. Verificar que no exista ya
void agregarPrograma(int codigo, const char nombre[]){
    if (buscarPrograma(codigo) != nullptr){
        cout << "El programa con codigo " << codigo << " ya existe." << endl;
        return;
    }

Regla de negocio "código único" resuelta con un return temprano: si buscarPrograma ya lo encuentra, ni siquiera se llega a tocar memoria.

2. Crear el arreglo nuevo, copiar y llenar la posición nueva
    Programa *nuevoArreglo = new Programa[universidad.programasCount + 1];

    for (int i = 0; i < universidad.programasCount; i++){
        nuevoArreglo[i] = universidad.programas[i];
    }

    nuevoArreglo[universidad.programasCount].codigo = codigo;
    strcpy(nuevoArreglo[universidad.programasCount].nombre, nombre);
    nuevoArreglo[universidad.programasCount].estudiantes = nullptr;
    nuevoArreglo[universidad.programasCount].estudiantesCount = 0;

new Programa[N+1] reserva un arreglo un espacio más grande que el actual. El for copia los N programas viejos tal cual estaban. La última posición (índice N, el tamaño viejo) se llena a mano — y estudiantes = nullptr / estudiantesCount = 0 son obligatorios: ese programa nuevo todavía no tiene hijos.

3. Liberar el arreglo viejo y reasignar
    delete[] universidad.programas;

    universidad.programas = nuevoArreglo;
    universidad.programasCount++;

    cout << "Programa creado correctamente. Codigo: " << codigo << endl;
}

El delete[] va después de terminar de copiar y llenar — si fuera antes, se liberaría memoria que el for de arriba todavía necesita leer. Recién ahí se reasigna el puntero al arreglo nuevo y sube el contador.

agregarEstudiante() — mismo patrón, un nivel más abajo, dividido en validación + inserción.

1. Validar programa y documento único
void agregarEstudiante(int codigoPrograma, const char nombre[], const char documento[], const char telefono[]){
    Programa *programa = buscarPrograma(codigoPrograma);
    if (programa == nullptr){
        cout << "No existe un programa con codigo " << codigoPrograma << endl;
        return;
    }
    if (buscarEstudiantePorDocumento(documento) != nullptr){
        cout << "Ya existe un estudiante con el documento " << documento << endl;
        return;
    }

Dos reglas de negocio distintas, dos return tempranos: "debe pertenecer a un programa existente" y "documento único en toda la universidad" (no solo en el programa).

2. Generar ID e insertar
    int nuevoId = generarIdEstudiante();
    insertarEstudiante(programa, nuevoId, nombre, documento, telefono);

    cout << "Estudiante creado correctamente. ID asignado: " << nuevoId << endl;
}

La mecánica de crecer el arreglo (new N+1 → copiar → delete[]) vive aparte en insertarEstudiante, no acá — agregarEstudiante solo valida y genera el ID. Esa separación es la que permite reutilizar insertarEstudiante en el Bloque 2 (cargar desde disco) y el Bloque 4 (cargar desde CSV) sin duplicar código.

buscarPrograma()
Programa* buscarPrograma(int codigo){
    for (int i = 0; i < universidad.programasCount; i++){
        if (universidad.programas[i].codigo == codigo)
            return &universidad.programas[i];
    }
    return nullptr;
}

Recorrido lineal simple: el arreglo no está ordenado por código, así que no hay atajo. Devuelve &universidad.programas[i] (la dirección de esa posición, no una copia) para que quien llame pueda modificarlo directamente; nullptr si no aparece.

buscarEstudiantePorDocumento()
Estudiante* buscarEstudiantePorDocumento(const char documento[]){
    for (int p = 0; p < universidad.programasCount; p++){
        Programa &prog = universidad.programas[p];
        for (int e = 0; e < prog.estudiantesCount; e++){
            if (strcmp(prog.estudiantes[e].documento, documento) == 0)
                return &prog.estudiantes[e];
        }
    }
    return nullptr;
}

Dos for anidados porque hay que bajar dos niveles: universidad → programas → estudiantes. Recorre todos los programas (no uno solo) porque el documento debe ser único en toda la universidad. strcmp(...) == 0 es la forma correcta de comparar char[] — == compararía direcciones, no contenido.

generarIdEstudiante()
int generarIdEstudiante(){
    int id;
    bool repetido;
    do{
        id = rand() % 90000 + 10000;
        repetido = false;
        for (int p = 0; p < universidad.programasCount && !repetido; p++){
            for (int e = 0; e < universidad.programas[p].estudiantesCount; e++){
                if (universidad.programas[p].estudiantes[e].id == id){
                    repetido = true;
                    break;
                }
            }
        }
    } while (repetido);
    return id;
}

rand() % 90000 + 10000 siempre da un número de 5 cifras (10000 a 99999). El do-while vuelve a tirar el dado si ese número ya existe entre todos los estudiantes — necesita un do-while (no un while) porque el primer intento siempre tiene que probarse al menos una vez antes de poder preguntar "¿está repetido?".

🎤 Preguntas típicas de sustentación

¿Por qué necesitas estudiantesCount si ya tienes el puntero?
Un puntero solo guarda una dirección de memoria. sizeof() sobre él da el tamaño del puntero (8 bytes), no el número de elementos reservados — sin el contador no hay forma de saber hasta dónde recorrer el arreglo.
¿Por qué no usar vector si sería más fácil?
El enunciado lo prohíbe explícitamente: hay que demostrar el manejo manual de new[]/delete[] y el redimensionamiento, que es justo lo que califica el 35% de memoria dinámica.
¿Qué pasa si haces delete[] antes de copiar todo?
Liberas memoria que el ciclo de copia todavía está leyendo → comportamiento indefinido. Por eso el delete[] del arreglo viejo siempre va después de terminar de armar el nuevo.

eliminarEstudiante(documento): mismo patrón pero al revés — reservas un arreglo de tamaño N-1, copias todos los elementos excepto el que se elimina (saltas esa posición al copiar), delete[] el arreglo viejo, reasignas el puntero, y bajas el contador en vez de subirlo. Antes de copiar, valida con buscarEstudiantePorDocumento que sí exista.

actualizarTelefono(documento, nuevoTelefono): no necesita crecer ningún arreglo — busca el estudiante con buscarEstudiantePorDocumento (que devuelve Estudiante*, no una copia) y haces strcpy(est->telefono, nuevoTelefono) directo sobre esa dirección de memoria.

contarEstudiantesPorPrograma(): no crea nada nuevo, solo recorre — un for sobre universidad.programas imprimiendo prog.estudiantesCount de cada uno. Útil para entender la diferencia entre "crear/crecer" (necesita el patrón de 5 pasos) y "solo consultar" (no lo necesita).

Bloque 2 — Persistencia binaria

Carga automática de los .dat al iniciar, sobrescritura íntegra y liberación total al salir.

✓ Aprobado — 10% persistencia + 10% liberación de memoria
📋
"Al iniciar: lee los archivos binarios, toda la información en memoria dinámica" · "Al salir: eliminar los archivos anteriores, escribir nuevamente los .dat, liberar toda la memoria con delete[]".
⚠️
Los structs del Bloque 1 tienen punteros (Estudiante*, Matricula*). Escribir write((char*)&programa, sizeof(programa)) guardaría esa dirección de memoria como si fuera un dato — al recargar el archivo, esa dirección ya no significa nada. Por eso se usan structs "de disco" sin punteros.
structs de disco (sin punteros)
struct ProgramaDisco{
    int codigo;
    char nombre[50];
};

struct EstudianteDisco{
    int idPrograma;   // clave foranea: a que programa pertenece
    int id;
    char nombre[50];
    char documento[20];
    char telefono[20];
};

struct MatriculaDisco{
    int idEstudiante; // clave foranea: de que estudiante es
    int id;
    char codigoMateria[10];
    char nombreMateria[40];
    float notas[3];
    float definitiva;
    Fecha fecha;
};

La clave foránea manual

EstudianteDisco guarda idPrograma y MatriculaDisco guarda idEstudiante — sin eso, al leer el archivo plano no habría forma de saber a quién pertenece cada registro. Mismo concepto que un FK relacional.

Pequeño ajuste al Bloque 1

Se separó insertarEstudiante/insertarMatricula (solo la mecánica de crecer el arreglo) de agregarEstudiante/agregarMatricula (valida + genera ID + llama al insertar) — así la carga puede reutilizar el ID original en vez de generar uno nuevo.

cargarUniversidad() en sus 3 fases — el orden de lectura no es arbitrario.

1. Programas primero
void cargarUniversidad(){
    ifstream archivoProgramas("programas.dat", ios::binary);
    if (archivoProgramas.is_open()){
        ProgramaDisco pd;
        while (archivoProgramas.read((char*)&pd, sizeof(pd))){
            agregarPrograma(pd.codigo, pd.nombre);
        }
        archivoProgramas.close();
    }

archivoProgramas.read((char*)&pd, sizeof(pd)) lee exactamente sizeof(ProgramaDisco) bytes del archivo y los vuelca en pd, registro por registro — igual devuelve el stream, que en el while se evalúa false cuando ya no hay más bytes que leer. Van primero porque los estudiantes del siguiente paso van a necesitar buscarPrograma() para engancharse a uno que ya exista.

2. Estudiantes, enganchados por idPrograma
    ifstream archivoEstudiantes("estudiantes.dat", ios::binary);
    if (archivoEstudiantes.is_open()){
        EstudianteDisco ed;
        while (archivoEstudiantes.read((char*)&ed, sizeof(ed))){
            Programa *programa = buscarPrograma(ed.idPrograma);
            if (programa != nullptr){
                insertarEstudiante(programa, ed.id, ed.nombre, ed.documento, ed.telefono);
            }
        }
        archivoEstudiantes.close();
    }

Cada registro trae su idPrograma (la FK). Se busca ese programa en memoria y, si existe, se le engancha el estudiante con insertarEstudiante — usando el ed.id que ya trae el archivo, no uno nuevo.

3. Matrículas al final
    ifstream archivoMatriculas("matriculas.dat", ios::binary);
    if (archivoMatriculas.is_open()){
        MatriculaDisco md;
        while (archivoMatriculas.read((char*)&md, sizeof(md))){
            Estudiante *estudiante = buscarEstudiantePorId(md.idEstudiante);
            if (estudiante != nullptr){
                insertarMatricula(estudiante, md.id, md.codigoMateria, md.nombreMateria, md.fecha, md.notas, md.definitiva);
            }
        }
        archivoMatriculas.close();
    }
}

Van al final porque necesitan que su estudiante ya esté en memoria para poder buscarlo por md.idEstudiante con buscarEstudiantePorId. Si el orden de las 3 fases se invirtiera, esta búsqueda siempre fallaría (nullptr) porque el estudiante todavía no existiría.

guardarUniversidad() en sus 3 fases.

1. Borrar lo viejo y abrir los 3 archivos nuevos
void guardarUniversidad(){
    remove("programas.dat");
    remove("estudiantes.dat");
    remove("matriculas.dat");

    ofstream archivoProgramas("programas.dat", ios::binary);
    ofstream archivoEstudiantes("estudiantes.dat", ios::binary);
    ofstream archivoMatriculas("matriculas.dat", ios::binary);

remove() (de <cstdio>) borra el archivo del disco. Es literalmente "eliminar los archivos anteriores" del enunciado, antes de "escribir nuevamente los .dat" — sin este paso, si la universidad tuviera menos registros que antes, quedarían registros viejos pegados al final del archivo nuevo.

2. Recorrer la jerarquía completa y escribir cada nivel
    for (int p = 0; p < universidad.programasCount; p++){
        Programa &prog = universidad.programas[p];

        ProgramaDisco pd;
        pd.codigo = prog.codigo;
        strcpy(pd.nombre, prog.nombre);
        archivoProgramas.write((char*)&pd, sizeof(pd));

        for (int e = 0; e < prog.estudiantesCount; e++){
            Estudiante &est = prog.estudiantes[e];

            EstudianteDisco ed;
            ed.idPrograma = prog.codigo;
            ed.id = est.id;
            strcpy(ed.nombre, est.nombre);
            strcpy(ed.documento, est.documento);
            strcpy(ed.telefono, est.telefono);
            archivoEstudiantes.write((char*)&ed, sizeof(ed));

            for (int m = 0; m < est.matriculasCount; m++){
                Matricula &mat = est.matriculas[m];

                MatriculaDisco md;
                md.idEstudiante = est.id;
                md.id = mat.id;
                strcpy(md.codigoMateria, mat.codigoMateria);
                strcpy(md.nombreMateria, mat.nombreMateria);
                for (int n = 0; n < 3; n++) md.notas[n] = mat.notas[n];
                md.definitiva = mat.definitiva;
                md.fecha = mat.fecha;
                archivoMatriculas.write((char*)&md, sizeof(md));
            }
        }
    }

3 for anidados, uno por nivel de la jerarquía. En cada nivel se arma el struct "de disco" copiando campo por campo desde el struct real (llenando también la FK: ed.idPrograma = prog.codigo, md.idEstudiante = est.id) y se escribe con write() al archivo de ese nivel — los 3 archivos se van llenando en paralelo mientras se recorre una sola vez toda la estructura.

3. Cerrar archivos
    archivoProgramas.close();
    archivoEstudiantes.close();
    archivoMatriculas.close();
    cout << "Informacion guardada correctamente." << endl;
}

close() fuerza a que todo lo que quedó en buffer se escriba de verdad al disco — si el programa termina sin cerrar el archivo, se puede perder el último bloque de datos.

liberarMemoria()
void liberarMemoria(){
    for (int p = 0; p < universidad.programasCount; p++){
        Programa &prog = universidad.programas[p];
        for (int e = 0; e < prog.estudiantesCount; e++){
            delete[] prog.estudiantes[e].matriculas;
        }
        delete[] prog.estudiantes;
    }
    delete[] universidad.programas;
    universidad.programas = nullptr;
    universidad.programasCount = 0;
}

Libera de abajo hacia arriba: primero las matriculas de cada estudiante, después los estudiantes de cada programa, al final los programas. Si se hiciera al revés (delete[] universidad.programas primero), se perdería el único puntero que permitía llegar a los estudiantes y matrículas — quedarían huérfanos en memoria sin forma de liberarlos (memory leak).

🎤 Preguntas típicas de sustentación

¿Por qué no escribes el struct Programa directamente al archivo?
Porque tiene un puntero (Estudiante* estudiantes). Esa dirección de RAM solo es válida mientras el programa corre — al reabrir el .dat ya no significa nada. Por eso se usan structs "de disco" sin punteros y se reconstruye la jerarquía llamando otra vez a las funciones agregarX/insertarX.
¿Por qué agregarEstudiante ya no genera el ID al cargar desde archivo?
Porque el ID real ya fue asignado la primera vez que se creó el estudiante, y ya está referenciado como FK en matriculas.dat. Por eso se separó insertarEstudiante (mecánica pura) de agregarEstudiante (valida + genera + llama al insertar) — la carga usa el insertar directo con el ID original.

Agregar un 4to nivel (ej. Docente por Matricula): mismo patrón de 3 fases de cargarUniversidad pero con una fase más al final — necesita su propio DocenteDisco con una FK (idMatricula) y se lee después de matrículas, porque ese docente necesita que su matrícula padre ya esté en memoria para engancharse.

Porque write((char*)&struct, sizeof(struct)) escribe los bytes tal cual están en memoria — si EstudianteDisco no tiene el campo nuevo, sizeof no lo cuenta y esos bytes nunca llegan al archivo, aunque sí existan en el Estudiante en memoria durante la sesión.

Bloque 3 — Menú y registro

El bucle principal de 14 opciones, y las opciones 1-3 conectadas a las funciones del Bloque 1.

cin >> y cin.getline() no se llevan bien solos

Después de un cin >> variable queda un '\n' pendiente en el buffer. Si el siguiente cin.getline() no lo limpia con cin.ignore(), lee una línea vacía. Por eso cada función de registro alterna: leer número/token con cin >>, luego cin.ignore(), luego cin.getline() para lo que sí puede traer espacios (nombre, materia).

El switch salta el 4 a propósito

Como quedó en la Vista general: el enunciado no tiene opción 4, así que el switch simplemente no tiene case 4 — cualquier otro número no listado cae en default.

🎤 Preguntas típicas de sustentación

¿Por qué usas atoi() en vez de leer directamente un int con cin?
strtok devuelve un char* (el texto del campo, ej. "101"), no un número. atoi convierte esa cadena de caracteres a int. No se puede leer con cin porque el dato no viene de consola, viene de un archivo ya cargado en memoria.
¿Qué pasa si llamas strtok(linea, ",") dos veces seguidas?
Reinicia el corte desde el principio de linea y devuelve otra vez el primer token — por eso solo la primera llamada de cada línea usa linea, todas las siguientes usan nullptr para continuar cortando la misma cadena donde se quedó.
¿Por qué no reutilizas agregarEstudiante() en vez de insertarEstudiante()?
agregarEstudiante llama a generarIdEstudiante() internamente y descarta el ID que trae el CSV. Como el archivo ya asigna un ID por estudiante, hay que usar la función que respeta un ID externo — la misma razón por la que cargarUniversidad() del Bloque 2 tampoco usa agregarEstudiante.

El encabezado "Programa,Documento,Estudiante,Promedio" se escribe una sola vez, antes de los dos for, calcando exacto el formato del ejemplo del enunciado. fixed << setprecision(2) (de <iomanip>) fuerza siempre 2 decimales — igual que 4.58 en el ejemplo, no 4.5833333. if (matriculasCount == 0) continue salta estudiantes sin materias, para no meter un promedio de 0/0 al reporte.

🎤 Preguntas típicas de sustentación

¿Por qué estos 4 reportes no piden ningún dato por consola?
Porque son reportes completos de toda la universidad, no consultas de un solo registro — recorren directamente la estructura en memoria (poblada por cargarUniversidad al inicio, o por lo registrado en la sesión) y vuelcan todo a archivo.
¿Para qué sirve setprecision(2) y qué pasa si no lo pones?
Sin setprecision, cout/ofstream imprime un float con su representación por defecto (hasta 6 dígitos significativos, con decimales que pueden variar) — fixed << setprecision(2) fija siempre 2 decimales exactos, que es lo que pide el formato del ejemplo (4.58, no 4.58333).

🔧 Si te piden un reporte nuevo

El esqueleto base: ofstream archivo("nombre.txt"), recorrer los niveles que necesites con for anidados, escribir cada línea con << separado por comas, archivo.close() al final.

Reporte solo de un programa (pide código): se le agrega un cin >> codigo y un buscarPrograma(codigo) al principio, como en listarEstudiantesPorProgramaMenu — y el recorrido ya no necesita el for más externo (el de programas), porque ya tienes el puntero al único programa que te interesa.

Reporte con encabezado de columnas (como reporte_promedios.txt): una sola línea archivo << "Col1,Col2,Col3" << endl; escrita antes del primer for, nunca dentro del ciclo — si queda dentro, el encabezado se repite en cada vuelta.

¿Por qué todos abren el archivo con ofstream y no con fstream? Porque solo se escribe, nunca se necesita leer de vuelta en la misma función — ofstream es la versión de fstream ya restringida solo a escritura, mismo principio que usar ifstream en cargarUniversidad porque ahí solo se lee.

    if (estudiante == nullptr){
        cout << "No existe un estudiante con el documento " << documentoEstudiante << endl;
        return;
    }

    for (int m = 0; m < estudiante->matriculasCount; m++){
        if (strcmp(estudiante->matriculas[m].codigoMateria, codigoMateria) == 0){

            return;
        }
    }

    for (int n = 0; n < 3; n++){
        if (notas[n] < 0.0f || notas[n] > 5.0f){

    int nuevoId = generarIdMatricula();
    float definitiva = (notas[0] + notas[1] + notas[2]) / 3.0f;

}
