1. Estructuras jerárquicas 10 pts

Criterio: implementa Parte, Trabajo, Carro, Cliente y Taller, incluyendo los punteros a arreglos dinámicos y sus cantidades.

"Taller → N Clientes → N Carros → N Trabajos → N Partes"

Código

struct Parte    { char codigo[10]; char nombre[40]; float valor; };
struct Trabajo  { char codigo[10]; char descripcion[60]; Parte *partes; int cantPartes; };
struct Carro    { char placa[10];  char marca[30]; char modelo[20]; Trabajo *trabajos; int cantTrabajos; };
struct Cliente  { char cedula[20]; char nombre[60]; Carro *carros; int cantCarros; };
struct Taller   { char nombre[60]; Cliente *clientes; int cantClientes; };
Copia literal de los structs sugeridos: cada nivel guarda un puntero al arreglo dinámico del nivel hijo más un contador (cant...) que lleva el tamaño real ocupado. Sin STL — el crecimiento de cada arreglo se hace a mano en las funciones agregar...().

2. agregarCliente() 12 pts

Criterio: crea nuevo arreglo dinámico, copia los existentes, agrega el nuevo, actualiza cantClientes, libera el arreglo anterior.

"void agregarCliente(Taller &t, Cliente c); — Debe aumentar dinámicamente el arreglo de clientes del taller, copiar los clientes existentes, agregar el nuevo cliente y liberar el arreglo anterior."

Código

void agregarCliente(Taller &t, Cliente c)
{
    Cliente *nuevoArreglo = new Cliente[t.cantClientes + 1];

    for (int i = 0; i < t.cantClientes; i++)
        nuevoArreglo[i] = t.clientes[i];

    nuevoArreglo[t.cantClientes] = c;

    if (t.clientes != nullptr)
        delete[] t.clientes;

    t.clientes = nuevoArreglo;
    t.cantClientes++;
}
Cinco pasos exigidos por el enunciado, en orden: (1) reservar arreglo de tamaño n+1, (2) copiar los n existentes, (3) escribir el nuevo en la última posición, (4) liberar el arreglo viejo (con chequeo de nullptr para la primera llamada, cuando clientes aún no apunta a nada), (5) reemplazar el puntero y aumentar el contador. Taller &t por referencia porque hay que modificar el taller original, no una copia.

3. agregarCarro() 10 pts

Criterio: mismo patrón que agregarCliente, un nivel abajo.

"void agregarCarro(Cliente &c, Carro a); — Debe aumentar dinámicamente el arreglo de carros del cliente."
void agregarCarro(Cliente &c, Carro a)
{
    Carro *nuevoArreglo = new Carro[c.cantCarros + 1];
    for (int i = 0; i < c.cantCarros; i++)
        nuevoArreglo[i] = c.carros[i];
    nuevoArreglo[c.cantCarros] = a;
    if (c.carros != nullptr) delete[] c.carros;
    c.carros = nuevoArreglo;
    c.cantCarros++;
}
Idéntico patrón que agregarCliente, pero operando sobre Cliente &c: el arreglo que crece es carros, no clientes. Repetir el mismo patrón en cada nivel es intencional — así el crecimiento manual es consistente en toda la jerarquía.

7. calcularTrabajo() 8 pts

"float calcularTrabajo(Trabajo t); [...] total = sumaPartes × 1.19."
float calcularTrabajo(Trabajo t)
{
    float sumaPartes = 0.0f;
    for (int i = 0; i < t.cantPartes; i++)
        sumaPartes += t.partes[i].valor;
    return sumaPartes * 1.19f;
}
Recorre partes[], suma valor, y al final multiplica por 1.19f (el sufijo f evita que el literal se interprete como double y fuerce una conversión implícita). Ejemplo del enunciado: 250.000 + 120.000 = 370.000 × 1.19 = 440.300 — el programa da $440300.03, la diferencia de centavos es precisión propia de float (así está tipado valor en el struct Parte), no un error de lógica.

8. calcularCarro() 5 pts

"float calcularCarro(Carro c); — Debe sumar el valor de todos los trabajos del carro."
float calcularCarro(Carro c)
{
    float total = 0.0f;
    for (int i = 0; i < c.cantTrabajos; i++)
        total += calcularTrabajo(c.trabajos[i]);
    return total;
}
La rúbrica exige explícitamente reutilizar calcularTrabajo() dentro de este bucle, en vez de recalcular sumas de partes a mano — así cada nivel de la jerarquía delega el cálculo al nivel inmediatamente inferior.

11. liberarMemoria() 10 pts

"Implemente una función liberarMemoria(Taller& t) que recorra la jerarquía desde el nivel más profundo (Partes) hasta el nivel superior (Clientes), utilizando delete[]."
void liberarMemoria(Taller &t)
{
    for (int i = 0; i < t.cantClientes; i++) {
        Cliente &cliente = t.clientes[i];
        for (int j = 0; j < cliente.cantCarros; j++) {
            Carro &carro = cliente.carros[j];
            for (int k = 0; k < carro.cantTrabajos; k++) {
                Trabajo &trabajo = carro.trabajos[k];
                if (trabajo.partes != nullptr) delete[] trabajo.partes;   // 1. Partes
                trabajo.partes = nullptr;
            }
            if (carro.trabajos != nullptr) delete[] carro.trabajos;      // 2. Trabajos
        }
        if (cliente.carros != nullptr) delete[] cliente.carros;          // 3. Carros
    }
    if (t.clientes != nullptr) delete[] t.clientes;                      // 4. Clientes
    t.cantClientes = 0;
}
El orden es el inverso exacto de cómo se construyó: primero se liberan las Partes de cada Trabajo (lo más profundo), después los Trabajo[] de cada Carro, después los Carro[] de cada Cliente, y al final el Cliente[] del Taller. Hacerlo al revés (por ejemplo borrar t.clientes primero) dejaría sin liberar toda la memoria de los niveles inferiores — un memory leak. Se llama justo después de reporte() en main(), como exige la restricción #9.
main() — carga → reporte → libera, sin pedir datos por consola, Taller local (no global). Total rúbrica: 100 pts
